## Project Overview

**AI-Powered Contract Risk Assessment and Legal Assistant** — a Generative AI / NLP project that:

1. Extracts key clauses from uploaded PDF contracts.
2. Performs risk assessment (legal, financial, compliance) and rates severity.
3. Recommends mitigation actions.
4. Provides a fine-tuned chatbot for conversational legal Q&A.

The project is delivered as a Streamlit application that is built and run inside Jupyter / Google Colab notebooks. There is **no standalone Python package** in this repo — everything lives inside two notebooks.

### `app.py` (generated by cell 4) — three logical sections

**Section 1: Contract Analysis Workflow** (LangGraph state machine)

- `State` TypedDict carries: `pdf_path`, `chunks`, `vectorstore`, `key_clauses`, `risk_assessment`, `risk_assessment_report`, `recommended_actions`, `contract_text`.
- Nodes (in order): `extract_chunks` → `embedding_and_store` → `Clauses` → `generate_report` → `recommend_actions`.
- `extract_chunks` uses `DoclingLoader` + `HybridChunker` (tokenizer = `sentence-transformers/all-mpnet-base-v2`) and a `RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=100)`.
- `embedding_and_store` writes a Milvus collection (`docling_demo`) backed by a temp-dir SQLite-style file (`MILVUS_URI = mkdtemp()/docling.db`) using **FLAT indexing** (brute-force) — chosen deliberately for legal precision over speed.
- `key_clauses` retrieves top-k=5, then runs RAG via `create_retrieval_chain` + `create_stuff_documents_chain` with a structured clause-extraction prompt against `mistralai/Mixtral-8x7B-Instruct-v0.1` (`HuggingFaceEndpoint`).
- `generate_risk_assessment_report` reuses the retrieved `contract_text` and prompts `mistralai/Mistral-7B-Instruct-v0.3`.
- `recommend_actions` feeds the risk report into `mistralai/Mixtral-8x7B-Instruct-v0.1`.
- All LLM calls are wrapped in `torch.no_grad()`.

**Section 2: Fine-tuned Chatbot**

- Loads `ramonad2024/contract_lora_model` via `unsloth.FastLanguageModel.from_pretrained` with 4-bit quantization (`BitsAndBytesConfig`, `bnb_4bit_compute_dtype=torch.float16`).
- `generate_response(prompt)` runs sampled generation (`do_sample=True`, `top_p=0.9`, `max_length=50`).

**Section 3: Streamlit UI**

- `st.file_uploader` for PDF → temp file → tabs:
  - **📜 Analyze Contract**: triggers `risk_graph.invoke(...)` and surfaces `key_clauses`, `risk_assessment_report`, `recommended_actions` via a `selectbox`.
  - **💬 Legal Assistant**: chat interface that calls `generate_response` and persists history in `st.session_state.messages` / `st.session_state.chat_history`.

## Tech Stack

- **Python 3** (Jupyter / Google Colab kernel)
- **LangChain** + **LangGraph** — RAG pipeline and stateful workflow
- **Docling** + `HybridChunker` — PDF parsing with structure preservation
- **Milvus** (`langchain_milvus`) — vector store with FLAT index
- **Hugging Face Transformers** + `HuggingFaceEndpoint` — Mixtral-8x7B / Mistral-7B inference

- **Streamlit** — UI
- **pyngrok** — exposes Colab Streamlit on a public URL

## Development Workflows

This project is **Colab-first**. There is no local virtualenv, no test suite, no linter, no CI.

### Running the contract analysis app (Colab path)

1. Open `Contract_Risk_Assessment.ipynb` in Colab with a GPU runtime.
2. Run cell 2 to install dependencies.
3. Edit cell 4 and replace the `HF_TOKEN = "****"` placeholder with a real Hugging Face token (one that has access to the gated Mixtral / Mistral models).
4. Run cell 4 to write `app.py`.
5. Run cell 6 to launch Streamlit in the background.
6. Run cells 15–16: set `ngrok.set_auth_token("YOUR_AUTHTOKEN")` and `ngrok.connect(8501)` to get a public URL.

### Running the contract analysis app locally (not officially supported)

The README suggests `pip install -r requirements.txt && streamlit run app.py`, but **neither file exists in the repo**. To run locally you must:

1. Install the dependencies listed in cell 2 of `Contract_Risk_Assessment.ipynb` manually.
2. Execute cell 4 of the notebook (or copy its body, minus the `%%writefile app.py` magic) to create `app.py`.
3. Provide a valid `HF_TOKEN`.
4. `streamlit run app.py`.

Skip the `pyngrok` cells when running locally.

### Fine-tuning the chatbot

1. Place a `contract_finetuning.json` file (list of `{"question": ..., "answer": ...}` objects) next to the notebook.
2. Open `Finetuned_Model_for_Legal_Chatbot.ipynb` on a GPU runtime.
3. Replace the placeholder Hugging Face token in cell 2 (and cell 13 if pushing).
4. Run cells in order. Outputs land in `./outputs` (training) and `./lora_model` (saved adapter).

## Coding Conventions

Because the entire codebase is two notebooks plus one generated `app.py`, conventions are loose, but please follow what's there:

- **Notebook-first edits.** When changing application logic, edit cell 4 of `Contract_Risk_Assessment.ipynb` (the `%%writefile app.py` cell) — **not** a checked-in `app.py`. There is no `app.py` to edit; it's regenerated each run.
- **Keep the LangGraph workflow as the single source of truth** for the analysis pipeline. New analysis steps should be added as additional `graph.add_node(...)` + `graph.add_edge(...)` rather than ad-hoc Streamlit code.
- **Wrap LLM `.invoke(...)` calls in `torch.no_grad()`** (matches existing nodes).
- **Reuse `state['contract_text']`** for any new node that needs the original retrieved chunks rather than re-querying the retriever.
- **Prompt style:** existing prompts use markdown with emoji section headers (💡 Instructions, 🔍 Example Format, 📜 Contract Text, 📌 Output). Match that style for consistency unless explicitly asked to change it.
- **Constants live near the top** of the `%%writefile app.py` cell (`EMBED_MODEL_ID`, `GEN_MODEL_ID`, `MILVUS_URI`, etc.). Keep new constants there.
- **Do not change the Milvus index type** from `FLAT` without discussion — it was intentionally chosen for exact-match legal precision.
- **Section comments** in `app.py` use a banner style:
  ```python
  # ===============================
  # SECTION N: <name>
  # ===============================
  ```
  Preserve and extend that pattern.

## Editing Notebooks Safely

These notebooks are large (`Contract_Risk_Assessment.ipynb` is ~1.1 MB, mostly base64 PNG screenshots embedded in markdown cells 8/10/12/14). When editing:

- **Do not strip the embedded screenshots** unless asked — they are the project's documentation of UI behavior.
- Prefer the `NotebookEdit` tool over hand-editing JSON. If you must edit JSON directly, validate with `python3 -m json.tool` afterward.
- When inspecting cells from Bash, use Python rather than `cat` to avoid blowing context on the base64 blobs:
  ```bash
  python3 -c "import json; nb=json.load(open('Contract_Risk_Assessment.ipynb')); print(''.join(nb['cells'][4]['source']))"
  ```

## Known Gaps / Things to Watch

- The README references `requirements.txt` and `app.py` that **do not exist** in the repo. If you're asked to "fix the install instructions" or "add a requirements file", you'll need to create them from cell 2 of the main notebook.
- `key_clauses` uses the deprecated `retriever.get_relevant_documents(...)` API; LangChain's modern equivalent is `retriever.invoke(...)`. Don't change this opportunistically — only when explicitly asked.
- `generate_response` in `app.py` passes `eos_token_id=None` and a hard cap of `max_length=50`, which truncates chatbot answers aggressively. This is intentional-looking but may surprise users.
- Two different LLM endpoints are instantiated per analysis run (Mixtral-8x7B and Mistral-7B). Each call hits the Hugging Face Inference API and requires the token to have access to those gated models.
